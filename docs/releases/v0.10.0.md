# AuraScan v0.10.0

Released on 2026-08-30.

## Hostile AI And Repair Boundaries

- Package, upgrade, config-drift, incident, recovery, follow-up, and Repair
  Agent AI now use bounded duplicate-key-rejecting JSON with exact schemas and
  allowlisted identifiers. AI cannot lower deterministic severity, create
  download targets, establish trust, or acquire tool, URL, command, policy, or
  execution authority.
- Model-authored advisory prose is normalized and treated as untrusted
  interpretation. Recognized destinations, direct or indirect action requests,
  sentence-leading imperatives, package-helper advice, credential-transfer
  language, questions, terminal controls, and unsupported trust or compromise
  claims are rejected into fixed secret-free explanations. Lexical filtering is
  defense in depth, not proof that arbitrary language is harmless.
- The Policy-Gated Repair Agent replaces general shell behavior with a
  fail-closed local allowlist. Every exact command requires fresh foreground
  confirmation; only documented read-only diagnostics and constrained exact
  `/usr/bin/pacman` workflows are eligible. Remote, Git/AUR, build,
  interpreter, decode/eval, expansion, redirection, custom-executable, and
  direct AuraScan-modification paths are refused.
- Repair command input is closed, output is read in fixed chunks and capped at
  128 KiB, and the process group is stopped on timeout or excess output.
  Special devices, FIFOs, indefinite monitor/follow forms, and unsafe option
  operands are rejected before execution.

## Remote Stages And Opaque Carriers

- Package-scanner rule version `1.4.0` adds CRITICAL artifact-bound correlation
  for remote fetch or clone followed by execution in PKGBUILD, declared install
  hooks, built-package `.INSTALL` control text, and acquired source.
- Correlation follows bounded constant paths, pipeline filters, redirections,
  decoders, copies, and interpreter invocation. Unknown transformations that
  feed a later executed sink become HIGH incomplete-inspection blockers rather
  than false-clear or malware claims.
- New opaque-carrier rules detect local decode-to-artifact followed by
  execution and active interpreter or executable use of image, document, data,
  font, or media-named paths. File extensions, ordinary assets, unexecuted
  downloads, documentation, and quoted examples do not trigger the blocker.
- Vendored executable text receives normal bounded deep-static analysis instead
  of only a provenance label. Images and other opaque bytes are never rendered
  or sent to a multimodal model.

## Source, Archive, And Tool Hardening

- Deep-static acquisition parses the exact captured PKGBUILD, performs zero
  network requests under `--offline`, snapshots local files without following
  links, isolates source destinations, and blocks incomplete acquisition.
  Source URLs reject embedded credentials, localhost, and non-public IP
  literals before requests and after redirects; persisted metadata removes
  credentials, queries, and fragments.
- Source declarations now fail closed on malformed, dynamic, indirect,
  evaluated, sourced, read-populated, subscripted, or nameref-aliased mutation
  without executing Bash. Git and GPG use captured and revalidated trusted
  executables, isolated configuration, bounded runtime/output, and sanitized
  status data.
- Archive, acquired-source, built-package, and ClamAV inspection use bounded
  no-follow inputs, entry/output limits, transactional cleanup, option
  terminators, and fixed secret-free failures. Unsafe links, nested archives
  not recursively inspected, changing inputs, malformed `.PKGINFO` or
  `.INSTALL`, and invoked scans that do not complete fail closed.
- Upgrade preflight, notifications, ClamAV, Git, GPG, bsdtar, makepkg, pacman,
  sudo, and supported helper workflows capture and revalidate trusted absolute
  system executables rather than accepting hostile `PATH` replacements.

## Scope, Compatibility, And Packaging

- AuraScan remains a static safety layer, not a native-parser or build sandbox.
  Same-UID or root attackers, parser defects, DNS rebinding, unknown decoders,
  steganography, and code that later executes inside makepkg remain outside a
  proof of safety; untrusted builds still belong in a clean chroot or disposable
  environment.
- The application and Arch/AUR package advance to v0.10.0. The package-scanner
  rule version advances from `1.3.0` to `1.4.0`; scanner version remains
  `2.5.0`; Instruction Guard report schema and rule version remain `1.0`.
- CI keeps general and Instruction Guard AI disabled and tests Python 3.8 and
  3.14 without a live provider, real makepkg execution, root, or networked
  fixtures.
