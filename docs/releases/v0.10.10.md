# AuraScan v0.10.10

Released on 2026-09-12.

AuraScan v0.10.10 is a recovery-bearing release because signed runtime
intelligence changes shared scanner trust, cache/review identity, and package
installation decisions. The fresh recovery image and applicable validation
gates are recorded below, with its exact tested identity pinned in the
packaged manifest.

## Independent detection data

- Introduces the separate runtime-intelligence schema `1.0` for the existing
  npm malicious-package versions, payload SHA-256 indicators, malicious domains,
  and emergency vendor advisories. The bundled baseline preserves their
  detection outcomes and source attribution. Exact observed releases remain
  distinct from explicitly supported broader advisories; a future campaign
  cannot inherit another campaign's claims. Redistribution rights and a
  documented review basis are required for publisher admission.
- Keeps fixed rule IDs, severities, evidence requirements and version semantics
  in application code. Records contain no executable rules, arbitrary regular
  expressions, scripts, AI instructions or policy overrides. The first vendor
  comparator supports canonical four-part Chromium versions; unsupported
  formats require an application update. Indicator withdrawals require newer
  source-attributed signed corrections.
- Captures one immutable snapshot per scan or audit. Reports, caches, history,
  review fingerprints and wrapper handoffs bind the intelligence identity;
  changed or missing identities require conservative scanning, including
  `new-only`. Upgrade projections retain each reported advisory's exact
  identity and version floor. Existing deep-static acquisition and allow-cache
  restrictions remain intact.
- Verifies a signed manifest, detached signature and bounded JSON payload with
  trusted GnuPG, private verification state, exact packaged fingerprints and
  no key retrieval or inherited configuration. Schema, digest, signer, issue
  time, expiry, sequence rollback and conflicting same-sequence content fail
  closed. Manifest validity is at most 30 days. Reimporting identical active
  bytes is a no-op.
- Separates unprivileged downloads from network-isolated privileged activation.
  Root-owned immutable generations, bounded no-follow reads, durable writes,
  serialized activation and an atomic state record preserve system-wide
  identity for users and root-run package hooks. Failed refreshes retain the
  previous verified generation. Expired verified records still detect with
  visible staleness and disabled shortcuts; corrupt active storage reports
  incomplete coverage and cannot silently allow an install.

**The production feed and signing keys remain unconfigured in v0.10.10.**
Bundled scanning works, but refresh, offline import and automatic-update
activation intentionally refuse until a separately reviewed application
release provisions production trust. No production signing key, intelligence
repository or live feed is created by this release. Developer-only contract,
validator, deterministic bundle builder and signing/publication guidance are
provided under `tools/intelligence_repository/` and excluded from the installed
runtime.

## Tray and command-line workflow

The tray menu adds **Update detection data**, **Automatic detection updates**
and **Detection data status**. Requests use fixed asynchronous unprivileged
service clients and ordinary desktop administrator authorization; the tray
never becomes root and AuraScan collects no password. Status displays validated
local data identity, activation time, freshness and observed timer/service
state. Opening a menu or running a scan never downloads anything. Child
lifetime/output bounds and shared Quit guards protect concurrent operations;
raw child output is not displayed. Stopping a client cannot cancel a service
transaction that systemd has already accepted.

The equivalent CLI provides `aurascan intelligence status`, `update`,
`import DIRECTORY` and `auto-update enable|disable`. The optional daily timer
ships disabled with randomized delay. Package installation enables no timer,
starts no download and requests no credentials. Detection data, ClamAV
signatures and application upgrades remain distinct operations.

Package-archive output also explains that no optional `.INSTALL` script is
normal and needs no AI review for that step. It does not claim the package is
safe or that other checks were skipped.

Application and Arch/AUR package advance to v0.10.10. Scanner version is
`2.6.0`, package-scanner rule version is `1.10.0`, and existing report readers
remain compatible with legacy reports lacking intelligence metadata. Python
runtime dependencies remain standard-library-only on Python 3.8+; GnuPG is
required for intelligence activation. All AI modes remain opt-in and are
explicitly disabled for image building and validation.

## Limits

A valid signature authenticates the configured publisher, not the accuracy of
an indicator, execution of package behavior or absence of compromise. This is
not a complete malware/CVE feed or a TUF implementation. Offline freshness
cannot reveal unseen newer releases or authenticate the host clock. Publisher
mistakes, key compromise, native-parser flaws and privileged host compromise
remain risks; key replacement or compromise recovery requires an application
update in this version. Normal scanning and Instruction Guard stay non-fetching,
and no scan data, project configuration or AI credentials enter the updater.
