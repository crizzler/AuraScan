## Pacman-hook upgrade reliability

AuraScan's pacman hook now distinguishes verified official repository archives
from local and AUR builds using the root-owned pacman sync databases. An
archive is treated as official only when both its filename and streamed
SHA-256 match the repository `%FILENAME%`/`%SHA256SUM%` binding. Verified
official archives receive a fast deterministic install-hook scan:

- routine systemd service management in an official package's install hook is
  recorded as LOW and does not request manual review;
- auxiliary ClamAV and AI scans are skipped for those verified archives;
- deterministic malicious behavior still blocks, including remote execution,
  credential access, unsafe SUID/SGID installation, or an unreadable install
  hook;
- local, AUR, unknown, checksum-mismatched, and stale-index archives keep the
  full scan and the existing blocking behavior.

The hook prints one compact transaction summary instead of a full report for
every package, and a blocked transaction now names the blocked packages and
their rule IDs. This removes the common false-positive failure where a
verified official package with a routine service unit or a ClamAV signature
match aborted a large repository upgrade.

Interactive `aurascan upgrade` also offers the isolated devtools AUR build as
the default choice when the backend is available; repository-only and
keep-blocked choices remain, and non-interactive runs keep the hard stop.
