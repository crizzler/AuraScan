## Pacman-hook transaction reliability

The pacman hook now accepts every SHA-256 published for the same versioned
archive filename across the configured repositories. Arch and CachyOS can
publish byte-different rebuilds under one filename; the cache archive is
verified when it matches any repository entry, so a valid CachyOS download no
longer falls back to a full scan because the Arch entry was read last.

A bounded ClamAV timeout or incomplete scan is now a visible manual-review
advisory rather than a transaction blocker. An incomplete auxiliary signature
scan is not malware evidence, and the deterministic install-hook and package
checks remain authoritative. Confirmed ClamAV signatures still block, as do
all deterministic CRITICAL findings. The hook prints a
`Review advisory (not blocking)` line naming the affected packages and rule
IDs so the coverage limitation is never silent.

The hook also stops printing a per-package audit header and a misleading
cache-resolution note during normal transactions. A non-existent absolute hook
target now warns and is skipped instead of raising a glob error.
