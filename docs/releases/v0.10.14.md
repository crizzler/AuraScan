## Pacman-hook cache identity

The hook no longer scans an unrelated older cache archive and labels it as the
package being installed. A bare hook target is always treated as a package
name, never as a same-named file or directory in the hook's working directory.
The bounded local pacman database supplies the installed version and
`INSTALLDATE`; when the cached archive's version differs and its mtime predates
that install date, the hook skips it and explains:

- the cached archive and version that were found;
- the installed version it is older than;
- that it is not the package the transaction is installing;
- that a local `-U` file must be scanned explicitly with
  `aurascan --pkg <file>`.

This fixes the confusing report where a local AuraScan upgrade displayed the
old cached `0.6.0-1` package while pacman was installing `0.10.13-1`. Verified
official archives still use the checksum-bound fast path, and cache archives
newer than the installed package still receive the full local scan.
