## Runtime-link repair after upgrades

A repository rebuild can add an ELF `DT_NEEDED` entry for a shared library
without declaring the provider package. The application then fails before it
can open. AuraScan now checks the installed files of repository packages
changed by an `aurascan upgrade` transaction:

- ELF headers, program headers, and dynamic sections are parsed statically; no
  package binary or dynamic loader is executed;
- a soname is accepted when it is present in the linker cache or bundled in the
  same package;
- a missing soname is resolved against the bounded official sync-database
  `%PROVIDES%` index;
- when exactly one official provider package is found and is not installed,
  AuraScan asks to install it through the same trusted sudo/pacman handoff used
  by the upgrade;
- confirmed signatures, package transaction checks, and the existing upgrade
  gates remain separate and authoritative.

The command can also be run directly after an upgrade performed by another
front end:

```bash
aurascan doctor --fix-runtime-links
```

It checks packages installed in the last 30 days by default. Use
`--runtime-link-package NAME` to target an installed package explicitly. The
current CachyOS `ungoogled-chromium-bin` case is detected because its binary
needs `libsimdutf.so.36` and the official `simdutf` package provides it; AuraScan
offers `sudo pacman -S simdutf` through the trusted handoff.
