## Runtime-link repair scoping

The runtime-link check introduced in v0.10.16 now inspects packages that ship
a desktop launcher first. This keeps automatic repair focused on user-facing
applications and avoids offering optional VLC plugins, Perl-loading helpers, or
private library directories as if they were broken desktop applications.

Recent-package selection is ordered by install time and installed size, so a
large browser package is inspected before a bounded scan can stop. The direct
form remains available:

```bash
aurascan doctor --fix-runtime-links
aurascan doctor --fix-runtime-links --runtime-link-package ungoogled-chromium-bin
```

The CachyOS `ungoogled-chromium-bin` regression is detected as
`libsimdutf.so.36` missing from `/usr/lib/chromium/chromium`; AuraScan resolves
the official `simdutf` provider and offers to install it through the trusted
sudo/pacman handoff. ELF parsing remains static: no inspected binary or dynamic
loader is executed. Unresolved providers, malformed files, and scan bounds are
reported as limitations rather than treated as proof of health.
