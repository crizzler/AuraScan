# AuraScan v0.10.4

Release date: 2026-09-06.

AuraScan v0.10.4 is a recovery-bearing release candidate. Publication remains
blocked until the fresh image and required gates below pass.

## pnpm and precompiled Python inputs

- Adds local pnpm build-tool exposure checks for active PKGBUILD/declared-hook
  dependency operations. A bounded, stable pacman record in the upstream
  affected ranges blocks; unknown/unsafe evidence blocks as incomplete
  coverage. The wrapper refreshes this evidence before final input capture,
  and relevant scans cannot reuse cached allow results.
- Checks acquired pnpm lockfile name fields and extracted `package.json`
  names for traversal independently of lifecycle scripts or archive layout.
  `--ignore-scripts` does not waive the manifest-name risk. Unsupported
  bounded YAML/JSON syntax or identity forms fail closed as coverage, while
  ordinary npm scopes remain valid. The verified upstream references are
  [CVE-2026-82392](https://github.com/pnpm/pnpm/security/advisories/GHSA-c59q-g84q-2gj5)
  and [CVE-2026-82393](https://github.com/pnpm/pnpm/security/advisories/GHSA-vq4v-j7r6-jq4m);
  this does not establish malicious AUR activity or successful exploitation.
- Includes non-executable `.pyc`, `.pyo`, `.pyd`, and `__pycache__` source
  carriers in bounded inspection. Presence is manual review, recognized
  unchecked PEP 552 headers receive HIGH review, and exact supported execution
  references block. Filename/header evidence does not authenticate bytecode,
  establish a source mismatch, or prove execution. No carrier is imported,
  unmarshaled, disassembled, or executed.
- Adds defanged metadata/bytecode regression fixtures and updates rule
  explanations. Package rule version becomes `1.6.0`; repository snapshot
  version becomes `1.1`. Application and Arch/AUR package advance to v0.10.4.
- Updates `AGENTS.md` and `SKILL.md` for Codex GPT-6 Astra with explicit task
  follow-through, bounded delegation, concise reporting, and proportional
  validation while preserving safety and publication consent boundaries.

## Agent Instruction Guard UX

- Separates suspicious content, changed or unsafe integrity state, incomplete
  scan coverage, and clean first-seen baseline enrollment instead of presenting
  every pending item as the same review alert.
- Adds foreground guided triage and one confirmed, transactional batch action
  for safely read clean first-seen files. Batch enrollment fails as a unit if
  any selected identity or hash changes or the report is incomplete or unsafe.
- Keeps clean enrollment neutral in the tray, routes agent-file review into
  guided triage, and reserves warning states for suspicious, changed, unsafe,
  or incomplete evidence.
- Preserves the raise-only AI boundary: models explain deterministic suspicious
  evidence but never receive clean file text or authorize trust, enrollment,
  disable, or rescan actions.
- Binds guided approve/disable decisions to the exact displayed report and
  content hash, serializes private-state mutations, and keeps interrupted
  enrollment transactions fail-closed until a complete scan of the exact
  transaction root revalidates every target instead of allowing a monitor race,
  unrelated-root scan, or partial page to replace reviewed evidence.

- Preserves pending Instruction Guard security alerts across scans of other
  roots and concurrent monitor updates. A stale clean tray status cannot
  silently acknowledge an unrelated or later suspicious-file alert; delivery
  acknowledgement follows a successful generic notification.

## Recovery distribution and boundaries

This recovery-bearing release publishes a fresh optional hybrid BIOS/UEFI
image as one indivisible set: `aurascan-recovery-0.10.4-x86_64.iso`, its
`.iso.sha256` sidecar, and sorted `.iso.packages.txt` manifest. The builder
rejects a GitHub release asset at or above 2 GiB. It requires fresh work and
output locations in a disposable Arch VM with externally bounded CPU, RAM,
and disk and no host disk or home shares.

Recovery remains optional. Locally built UKIs remain specific to the builder
kernel and disposable test keys; they are not universal download assets.
Every future release declares either `recovery-bearing` or `package-only`.
No previous release or tag is rewritten. A digest binds exact bytes, not
package safety, successful recovery, or the absence of every possible secret.

The package-scanner rule version advances to `1.6.0`, repository snapshot
version to `1.1`, and application and Arch/AUR package advance to v0.10.4.
Scanner version stays `2.5.0`, package scan-input version `2.0`, and Instruction
Guard schema/rule version `1.0`. All AI modes remain opt-in; image build and
validation disable them explicitly.
