# AuraScan v0.10.6

Release date: 2026-09-09.

AuraScan v0.10.6 is a recovery-bearing release because the npm intelligence,
source hashing, and lifecycle inspection boundaries are shared with recovery.
This is a release candidate; publication remains blocked until the fresh image
and every required gate below have completed against its exact source.

## Shai-Hulud npm intelligence and lifecycle inspection

- Adds offline, source-attributed intelligence for four observed malicious
  releases: `feishu-docx-mcp@0.3.2`, `bmc-i18n-extract-cli@1.1.1`,
  `blueai-cli@0.7.0`, and `bmc-translate-utils@1.1.1`. Supported package-manager
  install arguments and acquired package manifests, npm lockfiles, and
  shrinkwrap data selecting an exact tuple produce CRITICAL blockers. Broader
  package advisories and unresolved or different versions require HIGH
  provenance review; unlisted versions are not presumed safe.
- Hashes bounded, stable regular acquired source files, including renamed
  non-code assets, through no-follow reads. The captured-byte SHA-256
  `e37e3ddeeaaa9e0c4fdbcb829b4895a6521031c80053fc436625b61e6ee5b1a6`
  identifies the reported payload; a checksum mention alone is not a match.
  Literal network targets matching the confirmed `t[.]m-kosche[.]com` C2
  indicator are separate CRITICAL evidence. Quoted documentation, unrelated
  argument roles, and hostname suffixes do not establish a target match.
- Binds supported Bun/Node root-entry lifecycle launchers to the same captured
  package entry script. Correlated credential access, writes to agent/editor
  configuration, and network/publication behavior can produce a CRITICAL
  supply-chain finding. Credential access and correlated persistence also
  have separate HIGH findings. Ordinary `bun run index.js`, comments, quoted
  examples, token names, and the presence of `.vscode/tasks.json` or
  `.claude/settings.json` are insufficient on their own.
- Reports exhausted parser/read bounds, replacement, unresolved supported
  entries, and missing required evidence as incomplete coverage. Findings use
  bounded, secret-free reasons without retaining raw lifecycle commands.
- Adds inert campaign fixtures, synthetic hash signatures, positive and
  negative parser regressions, and full/smart policy checks. Registry
  availability or publish-time malware scanning, favorable metadata, accepted
  history, signatures, and AI cannot clear a deterministic campaign blocker.
  Tests never execute package payloads, fixture commands, or credential access.
- Updates `AGENTS.md`, `SKILL.md`, user and contributor documentation to retain
  the distinction between intelligence, static behavior, and host exposure.

The package-scanner rule version advances to `1.7.0`. Scanner version remains
`2.5.0`, package scan-input version `2.0`, repository snapshot version `1.1`,
Instruction Guard report/rule version `1.0`, analysis evidence `1.3`, AI
evidence `1.1`, and private continuation cursor `1.1` with legacy `1.0` reads.
Application and Arch/AUR package advance to v0.10.6. All AI modes remain opt-in;
image build and validation disable them explicitly.

Default scanning remains local and non-fetching; source acquisition requires
the explicit deep-static workflow. Unacquired dependencies, unexpanded nested
archives, and unsupported dynamic JavaScript remain outside complete
inspection. Neither these detections nor the intelligence update establish
that a payload executed, that this host is compromised, or that the reported
campaign reached the AUR. A zero-finding result is not proof of safety.

## Recovery distribution and boundaries

This recovery-bearing release requires a fresh optional hybrid BIOS/UEFI
image as one indivisible set: `aurascan-recovery-0.10.6-x86_64.iso`, its
`.iso.sha256` sidecar, and sorted `.iso.packages.txt` manifest. The builder
rejects a GitHub release asset at or above 2 GiB. It requires fresh work and
output locations in a disposable Arch VM with externally bounded CPU, RAM,
and disk and no host disk or home shares.

Recovery remains optional. Locally built UKIs remain specific to the builder
kernel and disposable test keys; they are not universal download assets.
Every future release declares either `recovery-bearing` or `package-only`.
No previous release or tag is rewritten. A digest binds exact bytes, not
package safety, successful recovery, or the absence of every possible secret.
