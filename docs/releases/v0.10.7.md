# AuraScan v0.10.7

Released on 2026-09-11.

AuraScan v0.10.7 is a recovery-bearing release because editor-task inspection,
source identity, and history/update policy boundaries are shared with recovery.

## Editor-task inspection

- Inspects exact `.vscode/tasks.json` files as bounded structural JSON/JSONC
  data in local package snapshots and explicit deep-static acquired source.
  A supported reachable automatic task invoking an interpreter on a
  font-, data-, media-, or document-named path produces the CRITICAL blocking
  `EDITOR-TASK-AUTORUN-CARRIER-001` finding. Workspace trust and automatic-task
  permission remain prerequisites; static launch intent does not establish
  execution, a working payload, or host compromise.
- Keeps labels, descriptions, comments, ordinary manual tasks, normal scripts,
  and mere asset presence separate from active task command fields. Malformed
  data, duplicate keys, ambiguous dependency labels, dependency cycles, and
  unsupported active syntax produce the HIGH blocking
  `EDITOR-TASK-INSPECTION-INCOMPLETE-001` coverage finding.
- Binds local task inspection to the same stable no-follow byte read and hash
  as repository identity: at most 32 task files, 1 MiB each, and 4 MiB combined.
  Exact task evidence survives declared-source exclusions, including a VCS
  alias naming `.vscode`. A changed task invalidates cached results; task and
  coverage blockers remain effective before smart/new-only policy decisions.
  Deep-static uses its existing acquired-tree bounds and never treats raw
  task JSON labels as shell commands.
- Adds inert curated positive/negative fixtures and regressions for captured
  bytes, replacement, symlinks, resource limits, policy, cache identity, and
  offline archive inspection. Fixture command strings and font-named marker
  files are never executed. These exposed examples do not measure campaign
  recall or establish an AUR PolinRider incident.

The supported Linux task subset does not validate fonts, resolve extensions,
implement arbitrary JavaScript deobfuscation or RPC/decrypt/eval dataflow, or
add standalone Instruction Guard task discovery. Unknown dynamic behavior
remains outside complete static inspection.

## Git source identity and maintainer history

- Preserves Git selector fragments in trust-diff identity. Changing a selector
  cannot qualify as ordinary version-only URL churn or bypass normal scanning.
  Unsupported, ambiguous, or non-full commit selectors cannot receive pinning
  reassurance and retain visible HIGH/manual-review metadata findings.
- Explicit Git acquisition resolves the intended branch/tag namespace or full
  commit to an exact commit identifier, checks out that hash detached, verifies
  final HEAD, and records `resolved_revision`. Git operations share one bounded
  deadline and revalidate the trusted executable. Inert local Git regressions
  require `git` in the Arch package's `checkdepends`.
- Describes added, changed, or removed local `# Maintainer:` comments as
  annotation changes. They do not verify AUR ownership transfer or orphan
  adoption. Review and normal scanning remain required; legacy display text
  discloses its unverified ownership inference. Upstream restoration, pushes,
  adoption requests, missing comments, and hosting reputation cannot grant
  ownership authority or reduce deterministic risk.

Default scans remain local and non-fetching, so they cannot observe unseen
remote ref movement. Explicit Git revision verification authenticates neither
author nor content and does not prove a later makepkg build uses those bytes.
Deep-static allow caching remains disabled; no new remote ownership collector
or history-rewrite detector is introduced.

## Developer security-data and evaluation groundwork

- Adds source-attributed research and evaluation guidance covering evidence
  claims, independent assessment, model/generation provenance, privacy,
  purpose-specific rights, and separation of training, development evaluation,
  and reserved private holdout lineages. Model size, novelty, or reduced refusal
  do not substitute for measured task-specific performance.
- Adds the Python 3.8+ standard-library metadata contract
  `aurascan-security-data/1.0` and offline validator. Explicit analysis,
  redistribution, training, commercial-training, and proprietary-provider
  permissions remain separate and inherit restrictions through actual
  derivation parents. Unknown rights do not become permission; historical
  public exposure does not authorize redistribution. Structural validation
  covers only supplied records and does not verify rights or factual labels.
- Adds explicit developer intake for selected inert fixtures, official Arch
  recipe histories, AUR metadata/recipes, local exported package observations,
  and manually supplied advisory references. Network acquisition requires its
  own invocation opt-in and fixed HTTPS adapters; it invokes no Git, package
  code, shell, scan engine, or model. HTTP service metadata does not establish
  a cryptographically verified Git graph or complete history.
- Uses bounded private content-addressed storage outside the checkout, stable
  no-follow reads, no-replace publication, immutable receipts, exact
  revision/content identity, and package-family lineage. Acquisition, candidate
  admission, scanner assessment, and explicit review retain separate evidence
  roles. Every candidate remains in quarantine with all eligibility flags
  false, including after review. No corpus-export or use-enablement command
  is added, and private seed bytes/evidence are not release artifacts.
- Documents partial inventories, missing ancestors and external contamination,
  withheld holdouts, predeclared acceptance criteria, and conservative future
  schema migrations. Existing full-pytest CI covers the developer tools; they
  are not imported by AuraScan's runtime or added as installed CLI entry points.
  No training, provider calls, operational-data collection, or automated
  publication follows from these changes.

See [security model research](../SECURITY_MODEL_RND.md),
[the metadata contract](../../security-data/README.md), and
[explicit security-data intake](../SECURITY_DATA_INTAKE.md) for the detailed
boundaries. User and contributor guidance, `AGENTS.md`, and `SKILL.md` preserve
these authority and evidence distinctions.

The package-scanner rule version advances to `1.9.0`. Scanner version remains
`2.5.0`, package scan-input version `2.0`, repository snapshot version advances
to `1.2`, and public report and Instruction Guard schemas remain unchanged.
Application and Arch/AUR package advance to v0.10.7. Runtime dependencies remain
standard-library-only on Python 3.8+. All AI modes remain opt-in; image build
and validation disable them explicitly. A zero-finding result is not proof of
safety.

## Recovery distribution and boundaries

This recovery-bearing release includes a fresh optional hybrid BIOS/UEFI image
as one indivisible set: `aurascan-recovery-0.10.7-x86_64.iso`, its
`.iso.sha256` sidecar, and sorted `.iso.packages.txt` manifest. The builder
rejects a GitHub release asset at or above 2 GiB. It requires fresh work and
output locations in a disposable Arch VM with externally bounded CPU, RAM,
and disk and no host disk or home shares.

Recovery remains optional. Locally built UKIs remain specific to the builder
kernel and disposable test keys; they are not universal download assets.
Every future release declares either `recovery-bearing` or `package-only`.
No previous release or tag is rewritten. A digest binds exact bytes, not
package safety, successful recovery, or the absence of every possible secret.
