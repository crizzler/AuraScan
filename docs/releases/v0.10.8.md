# AuraScan v0.10.8

Released on 2026-09-11.

AuraScan v0.10.8 is a package-only release. It adds a small offline emergency
vendor-advisory check to installed-package audit and normal upgrade evidence.
These paths are outside recovery workflows; recovery runtime, recipes,
dependencies, boot tooling and shared security boundaries are unchanged.

## Emergency vendor advisory evidence

- Adds the HIGH `SEC-KNOWN-EXPLOITED-VERSION-LAG` finding with
  source/category `vendor_emergency_advisory`.
  The initial curated entry checks the exact installed `chromium` package
  below Linux upstream version `153.0.8010.36` for CVE-2026-87491. It remains
  active offline and with `--no-arch-audit`, separate from official Arch
  advisories, malware incidents and out-of-date flags.
- Uses the [Google announcement](https://chromereleases.googleblog.com/2026/09/stable-channel-update-for-desktop_0808145027.html)
  and [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?field_cve=CVE-2026-87491),
  reviewed on 2026-09-11, for the Linux fix and known exploitation evidence.
  AuraScan's HIGH priority reflects exploitation evidence; it does not
  attribute a HIGH severity rating to Google. The CNA record's inconsistent
  structured interval is not mechanically imported. No introduced lower
  bound is established.
- Missing, unsupported, conflicting or duplicate version evidence and failed
  package queries retain partial coverage. The
  `SEC-VENDOR-ADVISORY-VERSION-UNRESOLVED` finding identifies unresolved
  version evidence without echoing untrusted version strings. Epoch and
  package revision bumps cannot masquerade as upstream fixes.
- A supported exact repository upgrade candidate reaching the fixed floor
  may resolve the HIGH warning while preserving the original audit evidence.
  AUR replacements, custom versions and unrelated updates cannot waive it.
  Current upgrade snapshots capture package names only, so this check remains
  unresolved there; the full security audit captures installed versions.
- Adds offline regressions using injected versions, fake query runners and
  temporary roots. Tests exercise affected/fixed versions, malformed and
  duplicate evidence, uncertainty, query failures and upgrade suppression
  without executing Chromium, package code or live advisory queries.

The mapping is compiled curated intelligence shipped with AuraScan, not a
separately signed or live-updated feed; `--refresh` does not update it. Captured
names and versions cannot authenticate official package origin, rule out
downstream backports or prove exploitation on this host, Linux targeting,
sandbox escape or compromise. Other Chromium forks, user-local installs and
unlisted vulnerabilities remain outside this check. At/above-floor versions
mean only that this advisory did not match, not that a package is safe.
No automatic package replacement or current repository availability query
is added.

Application and Arch/AUR package advance to v0.10.8. Security-audit report
schema remains `1.0` with the additive `vendor_emergency_findings` summary
count. Audits are regenerated; package-scanner rule/cache versions and public
package/Instruction Guard schemas remain unchanged. Runtime remains Python
3.8+ with standard-library-only dependencies, and AI remains separately opt-in.

## Release validation

Publication requires the complete source suite, compilation, presenter
audits, shell/unit and package-metadata checks, a clean Arch package build,
the exact-ref Python 3.8/3.14 CI matrix, and re-verification of the retained
image's public identity and digest. Recovery boot and live-scenario gates
are not rerun for this package-only release.
