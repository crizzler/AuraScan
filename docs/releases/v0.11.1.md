## Why this release is v0.11.1

The `v0.11.0` tag was created on 2026-10-24, but its tag workflow rejected the
release note: one of the note's words is treated as an unfinished-work marker
by the final-release gate. That tag stays at its original commit and is not
moved, and no v0.11.0 release, desktop package, or AUR update was published.
v0.11.1 carries the same application content with corrected wording, so the
published package always corresponds to an archive whose CI gate passed.

## Desktop evidence contract

`aurascan ui` is a new read-only command for desktop interfaces. It prints one
bounded JSON object with the contract string `aurascan-ui/1`:

- no arguments: check evidence, detection-data identity, and incident counts
  awaiting review, composed from evidence AuraScan already owns;
- `--report FILE`: a bounded projection of a saved scan report. Raw package
  bytes (`evidence_snippet`, `raw_output`, `technical_details`), absolute
  paths, finding identifiers, and file hashes are dropped, and display text is
  sanitized;
- `--actions`: the fixed action catalog. A renderer selects an action ID and
  its declared arguments, never a command. Actions that install or downgrade
  packages through sudo stay terminal-only, and
  `aurascan.core.ui_actions.verify_report_binding` provides the exact-report
  consent check for any future renderer-requestable mutation.

The command never changes policy or local state, never calls a model, never
runs a package manager, and opens no listener. Malformed, unknown, or oversized
evidence fails the whole snapshot instead of rendering a partial view.
Unreadable incident state is reported as unavailable, never as zero.

The optional Electron shell and the reference `aurascan-desktop` package are
source-tree artifacts; they are **not** part of this release or of the
published AUR package. Their design and boundary notes live in
`docs/DESKTOP_UI_DESIGN.md`.

## Unchanged boundaries

- The default scan remains local and non-fetching.
- AI remains opt-in, advisory, and unable to lower a deterministic result.
- Recovery runtime, recipes, boot tooling, and dependencies are unchanged.
- The pacman hook, the makepkg wrapper, and the upgrade handoff behave as in
  v0.10.19.

## Validation

- Complete Python test suite: must pass on the committed release candidate.
- Python 3.8 and 3.14 CI matrix: the exact release-candidate branch and tag
  workflows must pass; a skipped, cancelled, stale, or unrelated run does not
  satisfy this gate.
- Presenter, architecture, shell-syntax, unit, and package-metadata audits:
  must pass.
- Clean Arch package build and package pre-scan: must pass.
- Recovery ISO and local-UKI gates: not rerun for v0.11.1; the retained
  v0.10.11 image and its recorded gate results remain unchanged.
