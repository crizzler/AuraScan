# AuraScan v0.12.0

Released on 2026-10-24.

AuraScan v0.12.0 is a package-only release. The ISO and local-UKI gates were
not rerun for v0.12.0. The retained recovery image is
`aurascan-recovery-0.10.11-x86_64.iso` from the v0.10.11 release:

- URL: `https://github.com/crizzler/AuraScan/releases/download/v0.10.11/aurascan-recovery-0.10.11-x86_64.iso`
- ISO SHA-256: `df78c277c73349bab532c890789a476d0746a5a2b9dbab10307fd0c6c482841c`
- ISO size: `1637941248` bytes
- Validation UKI SHA-256: `dd002994c34f8d6a282cf1ef01780943e51dbe2ff306d1bedb738dbddd10ba52`

The preceding image remains the tested recovery image; no new recovery assets
were built, relabelled, or uploaded for this application release.

## Settings and credentials

`aurascan settings` is a new user-facing command that reads the invoking user's
own configuration and prints it as `aurascan-settings/1`:

- every secret-bearing setting is reduced to a presence boolean before the
  payload is built, so the serializer never receives a credential value;
- the provider inventory, model, endpoint, feature switches, and the
  configuration file's path, mode and readability are reported;
- `aurascan settings set-ai-key --provider ID` stores one credential read from
  stdin, writes the file atomically at mode `0600` inside a `0700` directory,
  and echoes neither the value nor a digest of it.

Storing a credential does not enable AI. When the enable flag is unset, an
explicit `AURASCAN_AI_ENABLED=0` is written, because the runtime otherwise treats
a present key as enabled.

## Bound Instruction Guard actions

`aurascan instruction-audit --approve` and `--disable` accept
`--expect-report-id` and `--expect-sha256`. The Guard already revalidated the
report identity and the candidate hash; the CLI now exposes them so that another
client can prove it acted on the evidence it displayed. A changed report or file
is refused, and the flags are rejected without an approve or disable action or
with a malformed digest.

## Desktop console

The optional Electron console under `desktop/` gained three views that read these
commands through fixed argument vectors:

- Settings shows the configuration state and stores one provider credential on
  the child's stdin;
- Agent files shows Instruction Guard candidates with their relative path, rule
  identifiers, severities, one-based line ranges and fixed reasons, and offers
  approve or disable bound to the displayed report and SHA-256;
- Incidents runs a diagnosis, shows its findings, and can acknowledge markers.

Operations that need root stay in the terminal; the console lists the exact
commands instead of running them. There is no root process, no privileged helper,
and no shell. The shell and the reference `aurascan-desktop` recipe remain
source-tree artifacts and are not part of this release or of the published AUR
package.

## Unchanged boundaries

- The default scan remains local and non-fetching.
- AI remains opt-in, advisory, and unable to lower a deterministic result.
- Recovery runtime, recipes, boot tooling, and dependencies are unchanged.
- The pacman hook, the makepkg wrapper, and the upgrade handoff behave as in
  v0.11.1.
- `aurascan ui` remains read-only: neither settings nor triage state is added to
  its snapshot contract.

## Validation

- Complete Python test suite: must pass on the committed release candidate.
- Python 3.8 and 3.14 CI matrix: the exact release-candidate branch and tag
  workflows must pass; a skipped, cancelled, stale, or unrelated run does not
  satisfy this gate.
- Presenter, architecture, shell-syntax, unit, and package-metadata audits:
  must pass.
- Clean Arch package build and package pre-scan: must pass.
- Recovery ISO and local-UKI gates: not rerun for v0.12.0; the retained
  v0.10.11 image and its recorded gate results remain unchanged.
