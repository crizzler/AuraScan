# AuraScan v0.12.1

Released on 2026-10-25.

AuraScan v0.12.1 is a package-only release. The ISO and local-UKI gates were
not rerun for v0.12.1. The retained recovery image is
`aurascan-recovery-0.10.11-x86_64.iso` from the v0.10.11 release:

- URL: `https://github.com/crizzler/AuraScan/releases/download/v0.10.11/aurascan-recovery-0.10.11-x86_64.iso`
- ISO SHA-256: `df78c277c73349bab532c890789a476d0746a5a2b9dbab10307fd0c6c482841c`
- ISO size: `1637941248` bytes
- Validation UKI SHA-256: `dd002994c34f8d6a282cf1ef01780943e51dbe2ff306d1bedb738dbddd10ba52`

The preceding image remains the tested recovery image; no new recovery assets
were built, relabelled, or uploaded for this application release.

## Tray opens the desktop console

The updater tray resolved "AuraScan Settings" to the guided terminal wizard even
when the optional desktop console was installed. It now resolves a launcher from
a fixed list and starts it without a shell and without root:

1. `/usr/bin/aurascan-desktop`, then
2. the invoking user's own `~/.local/bin/aurascan-desktop`, then
3. an `aurascan-desktop` entry on `PATH`.

"AuraScan Settings" opens the console on its Settings view, and a new "Open
AuraScan Console" entry appears when a launcher is present. When no launcher is
installed, "AuraScan Settings" keeps the guided terminal wizard, which remains
the supported fallback. The console accepts `--view <name>` for one of the
published views and ignores any other value.

## Console correctness

- Incident commands exit `40` (some evidence unavailable) or `41` (a prepared
  repair was not applied) while still printing a complete report. The console
  treated those as failures and marked a valid diagnosis as an error; it now
  accepts them and explains what the code means. `42` and `43` remain failures.
- The Actions view offers one "Open upgrade in terminal" button. An upgrade needs
  root, and the console never holds root or a password, so the fixed
  `aurascan upgrade` wizard keeps the preflight, the risk review, and the sudo
  prompt in one place.

## Unchanged boundaries

- The default scan remains local and non-fetching.
- AI remains opt-in, advisory, and unable to lower a deterministic result.
- Recovery runtime, recipes, boot tooling, and dependencies are unchanged.
- `aurascan ui`, `aurascan settings`, and the Instruction Guard binding behave as
  in v0.12.0.

## Validation

- Complete Python test suite: must pass on the committed release candidate.
- Python 3.8 and 3.14 CI matrix: the exact release-candidate branch and tag
  workflows must pass; a skipped, cancelled, stale, or unrelated run does not
  satisfy this gate.
- Presenter, architecture, shell-syntax, unit, and package-metadata audits:
  must pass.
- Clean Arch package build and package pre-scan: must pass.
- Recovery ISO and local-UKI gates: not rerun for v0.12.1; the retained
  v0.10.11 image and its recorded gate results remain unchanged.
