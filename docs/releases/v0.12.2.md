# AuraScan v0.12.2

Released on 2026-10-25.

AuraScan v0.12.2 is a package-only release. The ISO and local-UKI gates were
not rerun for v0.12.2. The retained recovery image is
`aurascan-recovery-0.10.11-x86_64.iso` from the v0.10.11 release:

- ISO SHA-256: `df78c277c73349bab532c890789a476d0746a5a2b9dbab10307fd0c6c482841c`
- ISO size: `1637941248` bytes
- Validation UKI SHA-256: `dd002994c34f8d6a282cf1ef01780943e51dbe2ff306d1bedb738dbddd10ba52`

The preceding image remains the tested recovery image; no new recovery assets
were built, relabelled, or uploaded for this application release.

## Authenticated official archives no longer abort a transaction on scan limits

A v0.12.1 upgrade of 47 repository packages was aborted by the pre-transaction
hook because `pkgfile 27-1.1`, a package verified against the signed CachyOS
sync database, tripped two bounded-inspection rules:

- `STATIC-REMOTE-STAGE-INSPECTION-INCOMPLETE-001`
- `SUPPLYCHAIN-NPM-INSPECTION-INCOMPLETE-001`

Both describe AuraScan's own parser and resource limits. They are coverage
results, not observed behavior, and treating them as transaction blockers
turned a limitation of the scan into a denial of service: no upgrade containing
that package could proceed.

For an archive authenticated by filename and streamed SHA-256 against the
registry, those two rules now remain HIGH-severity **manual-review advisories**
and no longer block. The advisory is still printed in the transaction summary
and recorded in the report, and local, AUR, stale, and mismatched archives keep
the blocker. Incomplete inspection is still never reported as clean.

## Unchanged boundaries

- The default scan remains local and non-fetching.
- AI remains opt-in, advisory, and unable to lower a deterministic result.
- Recovery runtime, recipes, boot tooling, and dependencies are unchanged.
- `aurascan ui`, `aurascan settings`, the Instruction Guard binding, and the
  tray and console behaviour behave as in v0.12.1.

## Validation

- Complete Python test suite: must pass on the committed release candidate.
- Python 3.8 and 3.14 CI matrix: the exact release-candidate branch and tag
  workflows must pass; a skipped, cancelled, stale, or unrelated run does not
  satisfy this gate.
- Presenter, architecture, shell-syntax, unit, and package-metadata audits:
  must pass.
- Clean Arch package build and package pre-scan: must pass.
- Recovery ISO and local-UKI gates: not rerun for v0.12.2; the retained
  v0.10.11 image and its recorded gate results remain unchanged.
