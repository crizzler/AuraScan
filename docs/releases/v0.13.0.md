## A JavaScript project is reviewed before npm install can run it

A file someone sends you can execute the moment you type `npm install`. The new
`aurascan npm-audit [PATH]` reviews that project first. It reads `package.json`
and only the project files named by the `preinstall`, `install`, `postinstall`,
and `prepare` commands, as inert text with bounded no-follow reads. It never
runs npm, node, a shell, the project, or a lifecycle script, and it never
contacts a registry.

Two blocking rules cover the observed install-time payload shapes:

- `SUPPLYCHAIN-NPM-INSTALL-ENV-EXFIL-EVAL-001` (CRITICAL, blocking): one
  install-time file reads environment variables, contacts a network
  destination, and evaluates dynamic code. That is the shape of a recruiter or
  "interview task" payload that harvests the environment and executes whatever
  the remote end returns.
- `SUPPLYCHAIN-NPM-INSTALL-REMOTE-SCRIPT-001` (HIGH, blocking): a lifecycle
  command pipes a download into a shell or interpreter.

Comments, strings, and regular expressions are not evidence, and a partial
chain is not reported as a backdoor. Anything the audit cannot inspect — a
malformed or oversized manifest, or a lifecycle entry that is missing, outside
the project, or a symlink — becomes
`SUPPLYCHAIN-NPM-INSPECTION-INCOMPLETE-001`, a manual-review coverage finding
rather than a clean result. Dependency lifecycle scripts are reported as
unknown, because resolving them needs package metadata that this offline audit
deliberately does not fetch.

Exit codes are `0` for no findings, `1` for any finding, and `2` for a usage or
path error. A clean report means the reviewed project files did not show these
patterns; it does not mean the project is safe to install.

## The desktop console reaches the audit

The Actions view of the optional AuraScan Desktop console now hosts the review.
The project folder is chosen in a native dialog in the main process, so the
renderer never supplies a path, and the shell runs only the fixed read-only
`npm-audit <path> --json` vector. Findings are shown as BLOCK or REVIEW with
their location and recommendation, and the report keeps the coverage strings
so a clean result is displayed as no proof of safety rather than as approval.

The console remains a separate artifact; the `aurascan-desktop` package is
prepared in `packaging/desktop/` and is not published yet. Until it is
installed, `aurascan npm-audit` is available from the command line.

## Unchanged boundaries

- The default package scan remains local, non-fetching, and non-executing.
- AI remains opt-in, advisory, and unable to lower a deterministic result.
- Recovery runtime, recipes, boot tooling, and dependencies are unchanged.
- `aurascan ui`, `aurascan settings`, Instruction Guard binding, the official
  archive advisory policy, the updater tray, and the incident views behave as
  in v0.12.2.

- Python 3.8 and 3.14 CI matrix: the exact release-candidate branch and tag

  satisfy this gate.

  pass.
- Desktop renderer: typecheck, production build, and the renderer test suite

- Clean Arch package build and package pre-scan: pass.
- Recovery ISO and local-UKI gates: not rerun for v0.13.0; the retained
  v0.10.11 image and its recorded gate results remain unchanged.
