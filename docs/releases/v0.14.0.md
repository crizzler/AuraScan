## A read-only MCP server exposes the detection layer to an agent

`aurascan-mcp` is a stdlib-only JSON-RPC 2.0 stdio server with four default
tools: `scan_content`, `scan_path`, `audit_agent_config`, and `security_audit`,
plus an opt-in `verify_evidence`. The first two port the reverse-AntiCopy
prompt-injection detector: a static, rule-based first signal for text that looks
like instructions aimed at an AI reader. The detector never executes, fetches,
writes, or blocks anything.

`audit_agent_config` audits an agent/MCP configuration document as inert text,
including `mcpServers` command behaviour. `security_audit` runs the existing
host audit in pinned offline mode: no network, no state writes, one bounded
`pacman -Q` read, and no removal or quarantine action.

All four tools carry `readOnlyHint: true`, `destructiveHint: false`, and
`openWorldHint: false`. The server is intended for registration with
`trust: untrusted` and a narrow per-tool allowlist; the four tools are not
containment, and a finding is evidence rather than proof of compromise.

## Snippet redaction

`scan_content` and `scan_path` now redact credential-shaped spans in the
optional snippets they return. The decoded side is redacted first; if it
contains a credential, the encoded `matched_text` is replaced whole with
`<redacted:encoded>` so the raw encoded blob cannot be decoded back. The
server reports `redaction_applied`, `redaction_classes`, and
`redaction_notes`; `snippet_policy` is present on every scan payload and
explicitly says the result is best effort, not a secret-free guarantee.
`include_raw_snippet` restores the unredacted copy per call. A token that
falls outside the matched span, or across the analyzer's 120-character
bound, remains a documented limitation.

## Evidence bundles

`scan_content` and `scan_path` can emit an evidence bundle when asked. The
opt-in `verify_evidence` tool checks that the bundle is internally consistent
and, when the source is supplied, re-derives the scan and compares the payload
hashes. It does not verify origin, truth, no-tamper, execution, file identity
beyond bytes, or the rule catalog; its `does_not_verify` list states those
limits on every result. It is not part of the four default registered tools;
an operator must add it to both the include and allowlist deliberately.

## Version and packaging

The Python package and wheel are version `0.14.0`. The AUR recipe under
`packaging/arch/` names the v0.14.0 tag but carries `sha256sums=('SKIP')`
because the tag and its source archive do not exist yet. After the public tag,
run `packaging/arch/pin-release-checksum.sh`; it downloads the exact GitHub
archive, replaces the placeholder, and regenerates `.SRCINFO`. The final release
gate rejects `SKIP`, so the recipe cannot be published with the placeholder.
The optional desktop recipe remains unpublished.
