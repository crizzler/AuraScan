## Split-package reachability false positive fixed

`AUR-REPO-INSPECTION-INCOMPLETE-001` no longer fires when a valid split-package
recipe reads `${pkgname}` in an ordinary value such as
`source=("${pkgname}-${pkgver}.tar.gz::...")`. One canonical top-level
`pkgname=` or `pkgname=(...)` declaration is resolved, and the declared
`package_*` functions are used for reachability. Arithmetic, subscript,
parameter-operator, declaration-target, computed-name, `eval`/`source`,
helper-mutation, multiple-declaration, `case`, numeric-`[[ ]]`, and top-level
heredoc forms still fail closed. The evidence names the construct family
instead of a bare "required path ambiguous".

The effective-command walk is bounded at eight prefix tokens and fails closed
if the bound is exhausted with a token remaining. Scalar assignment tails are
accepted only when they are the exact reference plus command separators, so
`x=$pkgname`, `x=${pkgname}`, `x="${pkgname}"`, and array `source=(...)` stay
inert, while `x=$pkgname"x"` and `x=${pkgname}-suffix` refuse. Pure-string
`[[ ]]` reads, including glob and regex right-hand sides, are accepted as
read-only; numeric and subscript forms refuse.

The real Shelly recipe now yields its two declared roots. It remains
incomplete through independent collector and `cd` layers (`_source_dir` taint,
multi-line loop command substitutions, compound `[[ ]]`, case arms, test
guards, and relative operands after `cd`). Those layers are separate work; this
release does not claim to unblock Shelly end to end.

Rule version: `1.15.0`.

## Configurable AI providers

AI access is data-driven. OpenAI-compatible services are table entries with a
`base_url` instead of branches in `build_request`, and the existing OpenAI,
DeepSeek, and OpenRouter URLs remain byte-identical. Anthropic and Gemini keep
their dedicated transports.

New presets:

- Venice.ai (`venice`)
- Refuseless (`refuseless`)
- ExperientialLabs (`experientiallabs`)
- Apinex (`apinex`)
- Xiaomi MiMo (`xiaomi`)
- `custom`, an OpenAI-compatible endpoint supplied by the user

A cloud preset owns its endpoint, so `AURASCAN_AI_BASE_URL` cannot redirect one
by typo. `custom` requires an explicit base URL and model; switching to it
refuses stale values. It accepts HTTPS anywhere, or plain HTTP only on a
loopback literal. Userinfo, query strings, fragments, control characters, and
literal private, link-local, multicast, or unspecified IPs are refused.
Redirects are refused for every transport.

Local presets and loopback `custom` endpoints use a proxy-free opener, so
`HTTP_PROXY` and `ALL_PROXY` never see the request line, prompt, or Bearer key.
Public `custom` endpoints keep normal environment-proxy discovery; a proxy
therefore sees that traffic. The policy is covered by permanent offline
regressions.

`aurascan settings set-ai-config` writes the provider, model, base URL, and
enable flag only when supplied. The write is atomic at `0600` in
`~/.config/aurascan/.env`, preserves the stored credential, clears a stale base
URL on a preset switch, and never enables AI implicitly. `set-ai-key` is
unchanged and still takes the key on stdin. Provider inventory remains in the
CLI; the desktop shell checks field shapes only.

The desktop Settings view adds a provider picker, a model field prefilled from
the preset, an endpoint field for `custom` and local providers, an off-by-default
enable switch with one consent line, and a credential field scoped to the
selected provider. The shell exposes one fixed `configure_ai` action and an
`aurascan:configure-ai` IPC channel. The configuration projection returns
presence booleans only; the fresh password input necessarily holds the
user-entered text until it is submitted on stdin, while no stored credential is
returned to the renderer.

## Known limits

- The residual Shelly collector and `cd` layers above remain unresolved.
- A public `custom` hostname is not re-resolved before use, so DNS rebinding
  remains a documented residual; redirects are still refused.
- Recovery-session AI prompts offer the custom endpoint but were not exercised
  against a live server.
- No local Python 3.8 run; CI covers 3.8 on Ubuntu 22.04 and 3.14 on
  Ubuntu latest. No exhaustive Bash-semantics proof.
- `packaging/arch/PKGBUILD` pins the public v0.15.0 source archive SHA-256 for
  the AUR recipe.
- The optional `aurascan-desktop` package under `packaging/desktop/` is
  prepared but not published.
