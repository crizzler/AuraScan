# AuraScan 0.15.1

Released on 2026-11-09.

This is a package-only security release. It retains the validated
`v0.10.11` recovery image (`aurascan-recovery-0.10.11-x86_64.iso`, released
2026-10-21). The ISO and local-UKI gates were not rerun for v0.15.1. The
retained image is published at
`https://github.com/crizzler/AuraScan/releases/download/v0.10.11/aurascan-recovery-0.10.11-x86_64.iso`
with SHA-256
`df78c277c73349bab532c890789a476d0746a5a2b9dbab10307fd0c6c482841c`.

## Security fixes

### MCP path containment

- The MCP file guard now binds the opened descriptor to the device and inode
  captured during resolution. The open uses `O_NOFOLLOW` and the descriptor's
  type, identity and size are checked before any bytes are read.
- A final-component symlink swap, a rename replacement, a parent-directory
  swap or a disappearance between resolution and open is refused with
  `path_changed`. No outside-root bytes are returned.
- A configured root that resolves to `/` is rejected at server startup and at
  the guard layer, including surrounding whitespace. Previously `/` made every
  path fail as outside the root instead of producing a clear configuration
  error.
- A same-inode, in-place rewrite after the identity check can still change the
  bytes that are read. The guard binds object identity and containment, not
  file immutability.

### User `makepkg.conf` guard

`aurascan-makepkg` already refused user-level overrides of the build script and
tool-selection keys. The guard now:

- recognizes `declare`, `readonly`, `typeset` and `local` declaration forms,
  option words, tabs and multiple assignments on one line;
- treats unquoted `;`, `&` and `|` as statement separators, and refuses
  source-time `${GUARDED=...}`/`${GUARDED:=...}` expansion assignments,
  arithmetic shapes and nameref declarations;
- refuses the code-loading environment keys the wrapper strips from its own
  environment, plus `PATH`, the tool-selection keys, and the makepkg-internal
  controls `CARCH`, `extra_environment`, `restore_envvars` and `shellopts`;
- refuses literal `$(...)`, backticks and `<(...)` outside single quotes, which
  execute while makepkg sources its configuration;
- reads the user configuration after the final scan-input recapture and
  before the makepkg handoff in both the direct and sandbox paths.

The guard is a bounded defense-in-depth check, not a sandbox. It does not
inspect compiler, linker or compression configuration. Names such as `CFLAGS`,
`CC`, `CXX`, `RUSTFLAGS` or `COMPRESS*` can still influence which programs or
code the build loads, so a user `makepkg.conf` remains trusted input for those
settings. End-to-end `makepkg` sourcing with a hostile configuration was not
executed in this release gate; the guard is checked against a real-bash
source-gate oracle and focused regression tests.

## Deferred

R8, the recovery-image validation gap when `ukify` is absent, is not fixed in
this package-only release. It changes recovery boot/image tooling and will be
handled in a recovery-bearing release with fresh ISO and UKI gates. The
retained `v0.10.11` image does not carry this fix.

## Compatibility

The verified release runtime is Python 3.14. Python 3.8 remains a compatibility
target but is not green in CI and is not verified for this release. Desktop
packaging is rebuilt at `0.15.1`; the renderer and snapshot contract are
unchanged.

## Verification

- Independent Red review: no blocker; the three low-severity observations were
  resolved (directory-swap diagnostic, whitespace root, guard-boundary
  wording) and the same-inode content boundary was documented.
- Independent Reviewer gate: `APPROVE` for the recorded package-only source
  slice, with R8 explicitly deferred.
- Focused MCP and makepkg tests: 285 passed.
- Full suite: 5,859 passed, 3 skipped.
- `compileall`, both presenter audits, and `git diff --check`: exit 0.
- Observed skips: the external fixture checkout is absent or dirty (1), and the
  optional Qt binding is not installed (2).

Known limits and accepted fail-closed cases are recorded in the private
security evidence and in `docs/REFERENCE.md`. The release does not claim that
a passing test proves the whole system secure.
