## Repository-provenance correctness

Every change in this release is in the static repository-provenance analysis
that inspects the files beside a PKGBUILD. Nothing here executes, imports or
builds a package, and no rule, severity or blocking decision was downgraded:
`AUR-REPO-INSPECTION-INCOMPLETE-001` stays HIGH and blocking, and incomplete
traversal remains a coverage finding rather than a malware claim.

### A single-line loop assignment now fails closed

A control-word-prefixed assignment inside one segment
(`for f in a; do lang=$(cat v); install "d/$lang" x; done`) was previously
lost, so taint dropped and a stale constant could fabricate an inspected path
with `complete=True`. That was a wrong-direction defect: AuraScan reported
coverage it did not have. The shape now fails closed exactly like its
multi-line spelling.

**This changes results.** A package whose PKGBUILD uses the affected forms now
reports an incomplete repository inspection instead of `complete=True`. That is
the intended outcome, not a regression: the earlier complete result was wrong,
and the manual review those forms always required is now required again. A
PKGBUILD that previously reported a complete repository result for such a form
should be expected to show the HIGH blocking `AUR-REPO-INSPECTION-INCOMPLETE-001`
until that review is done.

Assignments that precede a command name (`x=1 install ...`) remain untracked,
and control-prefixed `declare -n` namerefs remain tainted.

### Bounded expansion resolution

A bounded set of side-effect-free parameter expansions over constants the
analysis has already proven is now resolved: `${name}`, literal
`#`/`##`/`%`/`%%` trims, literal `/`/`//` substitutions, and
`${name:-word}`/`${name+word}` whose name is known. A path built from such a
literal value is no longer left as unresolved taint. Assignment forms
(`${name:=...}`, `${name=...}`), subscripts, substring offsets, indirection,
nested and glob-pattern forms stay fail closed and unchanged.

### Bounded `[[ … ]]` compounds

`&`, `|` and newline are masked inside bounded `[[ … ]]` spans before the
shared segmenter sees the text, so a compound conditional parses as one `[[`
command instead of splitting into a phantom command whose executable is the
next test operand. Operand order no longer changes the result; every unbounded
or unbalanced span keeps the previous split-and-fail outcome, and the shared
segmenter itself is unchanged.

### `case` arm patterns are match data

Arm pattern lists are blanked before the shared segmenter sees the text. Each
pattern used to become a phantom command, and the `*)` wildcard arm even
flipped repository completeness through the glob-ambiguity rule. The
`)`/`;;`/`;&`/`;;&` boundaries, the `case` word and every arm body stay intact,
so commands inside an arm are still analyzed and captured. Bash's optional
leading `(` group (`case $x in (a) …`) is treated as part of the pattern list,
so the `)` that closes it is the arm terminator instead of a subshell close; a
leading group therefore no longer blanks its own arm body and can no longer
hide an `install`. A pattern list that never reaches its `)` is malformed and
falls back to the unmasked text.

### Test-command operands

`[`, `[[` and `test` are classified instead of being treated as ordinary
operands. The builtin name is never a repository operand (its `[` character
used to trip the glob-ambiguity rule), and test arguments are classified
operator-aware: operands of file-test primaries (`-f`, `-d`, `-ef`, …) are
captured with the same cwd-joined ambiguity rules as transfer sources, while
string and integer comparison operands are data. Unrecognized or unbounded test
grammar withholds a complete result.

### Cache invalidation

Each change advanced the package-scanner rule version, from `1.15.0` to
`1.21.0`. Cached analysis results from earlier rule versions are not reused.

## Compatibility

The verified release runtime is Python 3.14. Python 3.8 remains a compatibility
target but is not green in CI and is not verified for this release. Desktop
packaging is rebuilt at `0.16.0`; the renderer and snapshot contract are
unchanged (`aurascan-ui/1`).
