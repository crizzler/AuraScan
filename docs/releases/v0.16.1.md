# AuraScan 0.16.1

Released on 2026-11-11.

This is a package-only release and maintenance update. It retains the validated
`v0.10.11` recovery image (`aurascan-recovery-0.10.11-x86_64.iso`, released
2026-10-21). The ISO and local-UKI gates were not rerun for v0.16.1. The
retained image is published at
`https://github.com/crizzler/AuraScan/releases/download/v0.10.11/aurascan-recovery-0.10.11-x86_64.iso`
with SHA-256
`df78c277c73349bab532c890789a476d0746a5a2b9dbab10307fd0c6c482841c`.

## Fixes

- `collect_system_snapshot` no longer crashes when `/boot` or `/boot/efi`
  exists but cannot be stat'ed by the invoking user. The unreadable path is
  omitted from the boot-path list instead of turning an upgrade preflight into
  a `PermissionError`.
- The intelligence download path falls back to the platform certificate store
  when OpenSSL reports no default CA file or directory. If no trust anchor is
  available, it fails closed with an `IntelligenceError` instead of exposing a
  raw `FileNotFoundError`.
- Cached downgrade selection uses version order to break timestamp ties, so
  the newest older package is selected when two cached archives share an
  mtime.
- `packaging/arch/pin-release-checksum.sh` now rejects only a checksum
  placeholder line, not the word `SKIP` in comments. The 0.16.0 release had to
  work around the broader check.

## Verification

- Python 3.8 source suite: `5909 passed, 3 skipped`.
- Python 3.14 source suite: `5909 passed, 3 skipped`.
- Both runs used `--ignore=.worktrees --ignore=packaging` to exclude local
  worktree and packaging-staging copies; these are not shipped test inputs.
- `compileall`, both presenter audits and `git diff --check`: exit 0.
- The 0.16.0 repository-provenance behavior and rule version `1.21.0` are
  unchanged. No scanner rule, severity or blocking decision was changed.
- Desktop packaging is rebuilt at `0.16.1`; the renderer and snapshot contract
  remain `aurascan-ui/1`.

## Deferred

R8, the recovery-image validation gap when `ukify` is absent, remains open and
requires a recovery-bearing release with fresh ISO and UKI gates. The retained
`v0.10.11` image does not carry that fix.

The release does not claim that a passing test proves the whole system secure.
