# AuraScan 0.17.0

Released on 2026-11-11.

AuraScan 0.17.0 is a recovery-bearing release because it changes recovery-image
validation. The recovery builder was exercised against the same candidate
commit, and the resulting ISO and local validation UKI passed the BIOS, UEFI
and Secure Boot gates below. The ISO carries the clean candidate's
`build-required` manifest placeholder; this record is the published identity.

## Recovery image validation

- `validate_recovery_image` now fails closed when `ukify` is unavailable. It
  appends `ukify is unavailable; the recovery image cannot be structurally
  validated.` and refuses the staged image instead of accepting byte and PE
  checks alone (R8).
- When `ukify` is available, validation requires a successful
  `ukify inspect`, the expected kernel version, and the
  `systemd.wants=aurascan-recovery.service` and
  `systemd.wants=aurascan-recovery-smoke-marker.service` markers.
- This changes what a recovery-bearing release is allowed to install. It does
  not add a new recovery runtime scenario or claim that the recovery image
  performs storage recovery.

## Recovery gates

- Hybrid ISO, SeaBIOS readiness: `pass`
- Hybrid ISO, ordinary OVMF UEFI readiness: `pass`
- Local validation UKI, ordinary OVMF UEFI readiness: `pass`
- Local validation UKI, disposable-key Secure Boot unsigned rejection and
  signed readiness: `pass`
- Expanded-artifact privacy/path audit and ISO package inventory: `pass`
- Strict sub-2-GiB ISO size gate: `pass`
- Deterministic Limine, systemd-boot, GRUB and recovery fixtures: `pass`

The Secure Boot gate used disposable OVMF owner keys. Its unsigned control was
rejected by firmware, while the signed validation UKI reached the fixed
readiness marker. The pass receipts record the readiness marker and the
unsigned-rejection control separately; raw serial logs were not published.

  remain `aurascan-ui/1`.

## Limits

The recovery markers prove the stated boot and service boundary, not storage
recovery. The encrypted Btrfs, ext4/LVM, network/offline, interrupted-package,
snapshot-confirmation and unknown-bootloader scenarios remain separately
documented and are not claimed as passing here. The release keeps production
feed and signing keys unconfigured.

The release does not claim that a passing test proves the whole system secure.
