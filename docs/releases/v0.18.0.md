# AuraScan 0.18.0

Release date: 2026-11-12.

AuraScan 0.18.0 is a recovery-bearing release because it hardens the recovery
executor's snapshot-id handling and its privilege boundary for host tools. A
fresh recovery ISO and local validation UKI are built from the final candidate
and must pass the BIOS, UEFI, Secure Boot, privacy and fixture gates before
publication.

## Recovery executor hardening

- The snapshot executors accept only a canonical ASCII decimal snapshot id:
  exact builtin `str` or `int`, no leading zeros, no signs, separators,
  whitespace, Unicode digits or traversal, with a fail-closed 19-digit bound.
  Integer and string zero canonicalize identically. The validator never invokes
  conversion hooks on an unsupported object and never raises. A canonical
  20-digit id that the producer can normalize is deliberately refused as a
  narrowing.
- Every host tool executed as recovery root is captured at its fixed
  `/usr/bin/<name>` identity and revalidated immediately before each use.
  Optional probes degrade like a genuinely absent tool; they never execute an
  untrusted identity. The R8 `ukify` fail-closed behavior and error text are
  unchanged.
- First-use refusals preserve the zero-progress wording only when no command and
  no target-state change occurred. Later failures report partial preparation,
  retain or restore backups according to verified bytes, stop the remaining
  repair commands, and preserve the existing rollback paths.
- The systemd-boot reinstall path remains refused; target-binary gates and
  command previews are unchanged.

## Limits

The recovery markers prove the boot and service boundary, not storage
recovery. Booted target-disk repair scenarios, real root-owned tool behavior,
the recovery image tool layout and the ISO/UKI/Secure Boot gates are not claimed
until their own executions are recorded. The release does not claim that a
passing test proves the whole system secure.
