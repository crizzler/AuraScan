# AuraScan v0.9.2

Released on 2026-08-30.

## AUR Maintainer-Worm Detection

- Added `SUPPLYCHAIN-AUR-REPO-PROPAGATION-001`, a CRITICAL hard blocker for
  deterministic PKGBUILD or declared install-hook control text that correlates
  a canonical AUR Git target, repository mutation or staging, and a non-dry-run
  push bound to that AUR endpoint or configured remote.
- Supports SSH, scp-like, and HTTPS AUR remotes, simple constant variables,
  direct push targets, configured remote aliases, clone-created origins, Git
  repository context options, and command wrappers. Evidence remains fixed and
  secret-free; enumeration, loops, SSH references, and dot-prefixed hooks are
  supporting labels only after the complete chain matches.
- Keeps AUR URLs, clone/fetch behavior, dry runs, explicit pushes to another
  host, incomplete correlations, comments, quoted documentation, inert arrays,
  and arbitrary release tooling found only in acquired deep-static source out
  of the blocker.

## Declared Install-Hook Integrity

- Added `INSTALL-HOOK-UNINSPECTED-001`, a HIGH hard blocker when one literal
  local `install=` target cannot be resolved and inspected safely. Dot-prefixed
  hooks are supported; missing, unreadable, unsafe, ambiguous, non-regular,
  replaced, or symlinked declared-relative targets fail closed.
- Install-hook resolution uses bounded no-follow reads and binds the exact raw
  hook bytes, status, and PKGBUILD snapshot into cache identity. A matching
  failure-state blocker may be cached, but an unresolved or changed hook cannot
  reuse or create an allow decision.
- Review fingerprints, manual-review history, history comparisons, and trust
  diffs use the same captured hook identity. `aurascan-makepkg` revalidates the
  complete input after scanning and again immediately before invoking the real
  makepkg executable.

## Agent Instruction Guard Review Explanations

- Terminal review now distinguishes integrity-only first-seen or changed-file
  review from suspicious-content findings and prioritizes suspicious files.
- Content findings report deterministic one-based line ranges, behavior labels,
  and fixed reasons without printing source snippets. A bounded incomplete scan
  is labeled as the current page with continuation still pending.
- Separately enabled AI receives only bounded opaque evidence IDs, fixed
  reasons, behavior labels, and deterministic locations. Its advisory rationale
  cannot invent lines, establish trust, lower deterministic severity, or claim
  execution or compromise. Clean first-seen files remain AI `not-needed`.

## Scope, Compatibility, And Packaging

- Static AUR-propagation evidence describes a potential chain; it does not prove
  package code ran, credentials were available, a push succeeded, repositories
  changed, or a machine or account was compromised.
- The package-scanner rule version advances from `1.2.0` to `1.3.0`, invalidating
  older cached package decisions. Instruction Guard's report schema and rule
  version remain `1.0`; no report-schema migration or new provider/network data
  flow is introduced.
- The application and Arch/AUR package advance to v0.9.2. CI remains Python 3.8
  and 3.14 with general and Instruction Guard AI disabled, no live provider,
  no real makepkg execution, no root requirement, and no networked fixtures.
